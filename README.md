# mqtt-mcp-bridge

Мост между MQTT и MCP (Model Context Protocol): даёт AI-агентам понятный доступ к IoT-устройствам и умному дому.

> Статус: идея и проектирование, кода пока нет.

## Проблема

Датчики, лампы, реле и хабы отправляют данные в MQTT-брокер (Mosquitto, EMQX, Zigbee2MQTT и т.д.), но AI-агенты (Claude, Cursor, ChatGPT, локальные модели) этих данных не видят. Существующие MQTT-MCP серверы обычно дают только низкоуровневые `publish` и `subscribe`, и агенту приходится перебирать сообщения по одному.

## Идея

Небольшой сервис на Go одним бинарником, который стоит рядом с брокером:

- слушает топики и хранит историю сообщений;
- сам находит устройства (retained-сообщения, Home Assistant discovery, Zigbee2MQTT);
- отдаёт агенту по MCP запросные инструменты, а не сырые сообщения;
- позволяет отправлять команды только разрешённым устройствам.

## Пример

> «Были ли ночью открыты окна и какая была влажность в спальне?»
>
> «Выключи свет везде, кроме спальни.»

Агент сам вызывает нужные инструменты моста и отвечает, без отдельного кода под каждое устройство.

## Планируемые инструменты

- `list_devices`: какие устройства есть и что они умеют;
- `get_state`: текущее состояние устройства или топика;
- `query_history`: история за период с фильтрами и агрегатами (мин, макс, среднее);
- `publish_command`: отправка команды с проверкой прав.

## Принципы

- Один статический бинарник, без Python и тяжёлых зависимостей.
- Любой MQTT-брокер.
- Безопасность по умолчанию: только чтение, запись разрешается явно по списку топиков.
- Запросы с фильтрами вместо перебора сообщений.
